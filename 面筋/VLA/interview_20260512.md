## 日期：20260512

### VLA 领域

**论文：（基于 Vega & π0.7 深度思考）**

1. [基础概念题] Vega 论文中提出了从"模仿驾驶 (Imitation Driving)"到"指令驾驶 (Instructional Driving)"的范式转变。请解释这两种范式在建模目标、数据依赖和泛化能力上的本质差异，以及为什么指令驾驶需要更强的监督信号。
   - **答案/思考提示**：模仿驾驶的建模目标是条件分布 $p(a_{1:T}|o_{1:T})$，给定观察序列直接回归动作，泛化能力受限于专家数据的分布覆盖；指令驾驶的建模目标是 $p(a_{1:T}|o_{1:T}, c)$，其中 $c$ 是自然语言指令，解耦了"做什么"（指令）与"怎么做"（动作），模型需要理解指令的语义并合成对应动作，泛化到未见的指令组合。指令驾驶需要更强的监督信号是因为语言指令空间远大于动作空间，同一动作可能对应多种指令（如"超车"和"从左边绕过去"），单纯模仿动作无法捕捉这种多对一和多对多关系。

2. [深度思考题] Vega 使用"未来帧图像生成"作为密集监督信号来解决稀疏动作监督问题。请分析：为什么图像重建 loss 能提供有效的动作级监督？这种监督信号是否可能引入虚假相关性（即模型学习到"好看的图像"而非"正确的动作"）？
   - **答案/思考提示**：图像重建 loss 本质上提供了envelope constraint——如果动作不正确，未来帧图像会与真实图像有明显差异（物理不合理、物体位置错误、碰撞等），因此正确的动作是生成正确图像的必要条件。这类似于 inverse dynamics model 的思想：正确的动作是观察变化的因果根。可能的虚假相关性风险：如果模型在某些状态下生成了"看似合理"但实际上并非由该动作引起的图像（比如从其他数据中学到的场景），可能误导策略。这种风险的缓解方式包括：① 与 action prediction loss 联合训练；② 使用对抗性训练让判别器判断action-observation 的一致性；③ 周期性用真实环境 rollouts 验证。

3. [优缺点对比题] π0.7 采用流匹配 (Flow Matching) 生成动作，而 Vega 使用扩散模型 (Diffusion)。请从数学框架、训练目标和推理效率三个维度比较这两种生成范式在 VLA 动作生成场景下的优劣。
   - **答案/思考提示**：数学框架：Flow Matching 将动作生成建模为 ODE 路径积分，学习从噪声到数据的向量场；Diffusion 将其建模为逐步去噪的马尔可夫链。训练目标：Flow Matching 使用 regression loss（预测每一步的 velocity），目标函数更简洁（单一 MSE）；Diffusion 使用 denoising matching，需要预测噪声 $\epsilon_\theta$。推理效率：Flow Matching 可以用少量 steps（5-20 步）生成高质量样本，Diffusion 通常需要 20-100 步。VLA 场景下，π0.7 的流匹配在 real-time control 中更有优势；但扩散模型在建模多模态动作分布时理论上更强大（每步都是条件分布），Flow Matching 在少步数时可能在高度多模态场景下出现 mode averaging。

4. [实践应用题] 假设你要将一个 VLA 模型（如 Vega）部署到车载嵌入式平台，平台仅有 8GB GPU 显存且需要 10Hz 以上的控制频率。你会从模型压缩、推理优化、架构改动三个层面分别采取哪些策略？
   - **答案/思考提示**：模型压缩：① 使用 INT8/INT4 量化视觉编码器和动作decoder；② LoRA/QLoRA fine-tuning 保留原模型能力同时降低显存；③ 知识蒸馏：小模型学习大模型的 action distribution。推理优化：① 视觉编码器预计算+缓存（观察变化慢，帧间复用）；② 动作 decoder 使用 5-8 步少步生成（Flow Matching 适合少步）；③ 使用 TensorRT 或 ONNX Runtime 优化；④ Action chunking（一次生成 10 步，降低控制频率要求）。架构改动：① 降低图像分辨率（如 224→128）；② 使用更轻量的视觉编码器（如 EfficientNetV2 而非 ViT-L）；③ 考虑分离式架构：视觉理解用云端，action generation 用本地小模型。

5. [深度思考题] MemoryVLA 中提出的"Cognition-Memory-Action"三层架构，与 Vega 中"多模态生成-规划统一框架"代表了 VLA 架构设计的两种不同哲学：模块化 vs. 端到端。请从训练效率、泛化能力、可诊断性和计算成本四个角度深入分析，哪种架构更适合当前的 VLA 发展阶段？
   - **答案/思考提示**：训练效率：端到端联合训练更快收敛但需要大规模数据；模块化可以分阶段训练，每阶段可用专门数据集。泛化能力：端到端在分布内强但分布转移时脆弱；模块化通过独立替换感知模块实现跨场景迁移（如换摄像头无需重训动作模块）。可诊断性：模块化天然可解释，哪部分出错一目了然；端到端是黑箱。计算成本：端到端需要同时更新所有参数，显存需求大；模块化可冻结感知编码器只训动作模块。当前阶段（数据有限、算力受限）模块化更实用；数据和算力充足时端到端能挖掘更深的跨模态关联。长远看，端到端是趋势，但需要解决"如何优雅地分模块训练"的问题。
